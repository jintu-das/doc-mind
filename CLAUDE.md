# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Doc Mind is a React + TypeScript frontend for an AI-powered document intelligence app (document ingestion, semantic search, AI assistant chat, and a corpus dashboard). Currently frontend-only with static/mock data — no backend or API integration exists yet.

## Commands

- `npm run dev` — start Vite dev server
- `npm run build` — type-check (`tsc -b`) then production build via Vite
- `npm run lint` — run ESLint over the repo
- `npm run preview` — preview the production build

There is no test runner configured in this repo.

## Architecture

**Routing**: File-based routing via TanStack Router (`@tanstack/router-plugin`). Route files live in `src/routes/`; `src/routeTree.gen.ts` is auto-generated by the Vite plugin on dev/build — never edit it by hand. Each route file exports a `Route` via `createFileRoute("/path")({ component })`. `src/routes/__root.tsx` wires the app shell (`RootLayout`) that every route renders inside.

**Layout shell**: `src/components/root-layout.tsx` composes the persistent app chrome: `AppSidebar` (nav defined in `src/components/app-sidebar.tsx`) + `SidebarProvider`/`SidebarInset` from the shadcn sidebar primitive, plus a skip-to-content link and TanStack Router devtools. Add new top-level pages by creating a route file in `src/routes/` and, if it belongs in primary nav, adding an entry to the `navMain` array in `app-sidebar.tsx`.

**Feature organization**: Page-specific logic and components live under `src/features/<feature>/`, e.g. `src/features/dashboard/` contains `dashboard-page.tsx` plus a `components/` subfolder for feature-only pieces (charts, tables). Route files under `src/routes/` stay thin and simply render the corresponding feature page component. Follow this pattern for new features rather than putting non-trivial logic directly in route files.

**UI components**: `src/components/ui/` holds shadcn-generated primitives (button, card, sidebar, table, tabs, chart, etc.). This project uses shadcn's `base-lyra` style (see `components.json`) with Tailwind v4, base color `stone`, and Lucide as the icon library. Use the `shadcn` CLI/skill to add new primitives rather than hand-writing them, so they stay consistent with the configured style and registries. Path aliases (`@/components`, `@/lib`, `@/hooks`, `@/ui`) are defined in both `components.json` and `tsconfig.app.json`/`vite.config.ts` — use the `@/...` alias for all internal imports.

**Styling**: Tailwind CSS v4 with no `tailwind.config.js` — configuration is CSS-based in `src/index.css` via `@theme inline` and `@custom-variant dark (&:is(.dark *))`. Design tokens (colors, sidebar, chart palette) are CSS custom properties mapped into Tailwind theme variables there; prefer using existing tokens (`bg-background`, `text-muted-foreground`, `--chart-1..5`, etc.) over introducing new raw colors.

**Charts**: Recharts-based chart components (e.g. `src/features/dashboard/components/ingestion-chart.tsx`, `corpus-coverage-chart.tsx`) are code-split via `React.lazy` and re-exported from a feature-local `lazy-charts.ts` barrel, then rendered behind `<Suspense>` with a `Skeleton` fallback. Follow this lazy-loading pattern for any new heavy/chart components rather than importing them eagerly.

**Accessibility**: Existing code sets `aria-hidden` on decorative icons, `aria-label`s on icon-only or ambiguous inputs, and a skip-to-main-content link in the root layout. Maintain these conventions when adding UI.

**cn utility**: `src/lib/utils.ts` re-exports `cn` from the `cn` package (not a hand-rolled `clsx`/`tailwind-merge` combo) — import `cn` from `@/lib/utils` for conditional class merging.
